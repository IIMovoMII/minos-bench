# Project 3 科学评测实施方案 v3（候选人已审核版）

状态：产品方案与正式题目 v1 内容方向已通过候选人口语审核；允许按执行任务书转换数据并实现离线规则和新有限矩阵；工程 freeze 前当前旧在线矩阵继续禁用  
日期：2026-08-02  
证据目标：面试级可信证据；不声称生产级统计可靠性  
方法目标：构题、评分、评分模型验证、人工边界、坏案例和版本决策体现成熟评测团队的方法质量  

## 1. 项目要回答的问题

项目评估四类典型 LLM 应用任务，不声称覆盖基础模型的全部能力：

1. 按要求生成内容；
2. 根据给定资料回答；
3. 多轮对话；
4. 结构化输出与工具调用。

主实验比较 Model A + Prompt V1 与 Model B + Prompt V1。提示词实验比较同一个较弱模型的 Prompt V1 与 Prompt V2。前者讨论模型配置差异，后者只讨论提示词变化；不得用 Model A 与 weaker model + Prompt V2 的差异归因提示词效果。

## 2. 能力、风险与构题

每题绑定具体能力、用户目标、失败行为、严重程度、测试类型、证据、检查权限、数据用途、来源和版本。题量不预先固定，由覆盖缺口决定。

高价值风险优先覆盖：正常、边界、明确失败、最小对照、不变性、诱骗和经人工确认的历史坏案例。不是每个能力机械凑齐所有类型。

四类任务重点如下：

- 内容生成：明确要求、禁止项、核心遗漏、无依据补充、输入不足时澄清；
- 有依据问答：核心结论支持、资料外主张、否定/限定/例外、决定性遗漏、资料不足或冲突、引用存在与引用支持；
- 多轮对话：有效旧条件、最新修改、撤销要求、人物/对象/时间/范围、缺失信息澄清和跨轮一致；
- 结构与工具：Schema、必填值、是否应调用、工具选择、参数含义、调用顺序、确认副作用、失败处理和工具结果使用。

完整安全红队、多模态、真实外部工具副作用和超长上下文不扩张为第五任务包；相关权限与副作用只作为横向风险。文风、长度和语言比例只有题目明确要求时才评分。

严重程度在看到模型答案前固定：影响核心结论、错误行动或证据真实性为严重；造成明显缺失或返工但核心结果仍可使用为重要；只影响表达体验为一般。

## 3. 检查器、评分模型与人工权限

判断权限分为：

- `DIRECT_VERIFIER`：完整、直接且与业务合同等价的代码核验，可以形成确定结果；
- `SIGNAL_ONLY`：关键词、正则、长度、语言比例等启发式，只提高复核优先级；
- 评分模型：逐项语义初审和证据整理，不决定严重程度或最终版本；
- 候选人参考判断：确认高风险语义问题、处理冲突并保存理由和证据。

每条语义小项只观察一个行为，并提前定义适用条件、可用证据、满足、不满足、无法判断、不适用、严重程度、判断权限和正反边界例。如果经常需要“部分满足”，继续拆分规则。

评分模型一次结构化请求返回同一道题全部适用小项：

```text
criterion_id
applicability: APPLICABLE / NOT_APPLICABLE
evidence_sufficiency: SUFFICIENT / INSUFFICIENT
decision: PASS / FAIL / ABSTAIN
answer_evidence
source_evidence
reason
```

评分模型不得看到待测模型名、运行别名和 Prompt 版本。严重程度由规则预先给出，评分模型不能临时修改。自报信心可保存观察，但不参与自动裁决。

明确失败只能来自提前定义的重要/严重直接核验失败，或人工确认的内容错误。评分模型未经独立验证的失败只进入复核。全部直接规则和适用语义项通过时称“机器初审通过”，不称客观真值。

## 4. 人工参考判断与评分模型体检

个人项目只有一名候选人，人工结果只称“候选人参考判断”，不称专家金标准。候选人先看到题目、规则、答案和证据，不看模型身份与评分模型结论；提交逐项判断和理由后再对齐机器结果。

人工材料按能力和风险选择，覆盖四类任务、严重风险、边界、最小对照、诱骗、评分模型弃权、机器冲突和真实坏案例。数量由覆盖矩阵决定，不预设任意整数。

评分模型体检依次关注：严重误放、明显错杀、证据充分时逃避判断、证据不足时虚假确定、证据引用错误和对表面流畅风格的偏好。平均一致率只是补充。

本项目不检查待测模型或评分模型的重复波动：每个冻结配置对每题生成一次，每份答案评分一次。不得声称统计稳定性、随机波动范围或评分模型可重复性。第二评分模型不默认加入，只有真实失败证据证明它能减少特定错误时才另行讨论。

评分模型即使只能整理证据或初步分流，项目仍成立；不通过无限修改提示词追求评分模型全部通过。

## 5. 数据用途与防泄漏

材料分为五种用途：规则开发、评分模型开发、评分模型验证、待测版本比较和回归。用于调规则或挑评分策略的题不得再用于证明评分模型可靠。

同一业务场景、改写题和最小对照属于同一个题目家族，必须整体进入同一种用途，不能拆到开发和验证两边。

现有 40 条主数据和 8 条封存题继续保留为工程基线、先导材料和封存流程证据，不承担统计代表性。根据新覆盖矩阵重新分配现有开发题用途；验证和比较材料形成独立版本并密封。新增题只补真实覆盖缺口。

真实运行后经人工确认的坏案例进入后续回归版本，不回写或改造已经完成的正式比较。

只修改评分规则或评分模型时，对不可变原始输出离线复评，不重新请求待测模型。只有待测模型、Prompt 或生成参数改变时才产生新的生成运行；新旧评分结果同时保留。

## 6. 一键有限矩阵与停止规则

保留离线、探针、技术路径试跑、开发运行、评分模型体检和封存题六个逻辑阶段，但候选人不需要逐阶段手动放行。设计、数据、规则和执行计划全部冻结后，一次主动启动自动执行预先声明的有限矩阵：

1. Model A + Prompt V1；
2. Model B + Prompt V1；
3. weaker model + Prompt V1；
4. weaker model + Prompt V2。

内部先完成离线门禁和 Provider 探针，再覆盖普通文本、资料回答、多轮、JSON 和工具回传等不同技术路径。机械合同通过后自动继续矩阵；内容质量不好不触发重生成、调规则、增加题目、增加重复或启动第二轮。

不设置累计请求或 Token 预算门禁，也不要求每阶段一次性授权。启动前展示预计请求量和 Token 范围，仅供知情。任务数量、每题调用路径和临时重试上限必须有限；“无限授权”不允许程序自行扩张矩阵。

鉴权、协议和不支持参数错误第一次出现立即停止。临时网络或超时只允许一次诊断性重试；同一运行错误再次出现即停止当前矩阵。质量失败绝不触发自动重试或重生成。

同一个执行编号重复启动时只恢复未完成部分，不重复已有原始输出。开始一轮全新矩阵必须由候选人再次主动操作并产生新执行编号；系统不会自动新建下一轮。

旧 `run_full_pipeline.ps1` 在新有限执行器完成本地验证前继续硬停止，不得恢复旧的三次 live + replay + 稳定性复评矩阵。

## 7. 结果、参考总分与版本建议

每轮同时保留机器初审报告与人工确认报告。人工结果追加保存，不能覆盖机器原始判断。

参考总分计算：满足为 1、不满足为 0；无法判断不进入得分但进入判断覆盖率；不适用排除。先对每题的已判断适用小项取平均，再对同一任务的题目取平均，最后对四类任务等权平均并换算为 0—100。

四类任务等权只表示本 POC 同等展示四类能力，因为没有真实业务流量可推导业务权重。若以后使用真实业务权重，必须产生新评分版本，不能看完结果后调权重。

报告至少并列显示：

- 机器初审参考分与人工确认后参考分；
- 四类任务分项；
- 运行完成率；
- 判断覆盖率；
- 人工复核覆盖率；
- 经确认的严重、重要和一般错误；
- 同题修复、退步、持平和无法比较；
- 人工推翻评分模型的情况。

运行失败不直接记内容 0 分；内容参考分必须与运行完成率并列。总分只用于快速理解，不能抵消严重错误或单独决定版本。

建议采用新版本需要：运行结果完整、没有新增经确认严重退步、预定目标能力出现修复、未以其他重要能力退步为代价，并且决定性差异已人工确认。证据不足时允许不作选择。

坏案例根因先写成假设；只有控制变量验证后才升级为根因。每个重要坏案例保存原始回答、违反小项、证据、机器与人工判断、严重程度、验证方法和回归状态。

## 8. 真实性与完成边界

最终报告必须主动说明：每配置每题单次生成、每答案单次评分、未测波动、数据以合成和公开资料为主、一名候选人参考判断、模拟工具不代表真实系统、结论只适用于冻结题目和配置。

可以声称完成了由能力风险矩阵、直接核验、原子语义初审、人工升级、参考总分、同题比较、坏案例回归和有限运行组成的可审计 LLM 应用评测流程。

不能声称评分模型达到生产可靠性、结果代表大厂真实流量、某模型普遍最佳、拥有真实企业客户或产生未经测量的效率与 ROI。

候选人仍须完成盲审、争议题判断、亲自启动、解释真实坏案例和无稿演示；Codex不得冒充这些工作已完成。
